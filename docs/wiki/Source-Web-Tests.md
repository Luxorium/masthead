# Page tests (web/vitest.config.ts, web/test/)

The tests for the page in Masthead 0.2.0: unit and component tests run by Vitest, and the browser test `test/ui.e2e.mjs`. How to run all tests and the latest results are on [Tests](Source-Tests.md); this page says what each page test file checks.

Run with `npm run test:web` (`vitest run --config web/vitest.config.ts`). The files below hold 108 `it()` tests in 21 files (counted in the source; `npx vitest run --config web/vitest.config.ts` on 2026-11-27 passed all 108).

## `vitest.config.ts` and `setup.ts`

`web/vitest.config.ts` uses the Svelte Vite plugin with the project's `svelte.config.js` and `dev: true`, `root: 'web'`, and the `browser` resolve condition (so Svelte's browser build is used, which component tests need). Tests run in **happy-dom** by default and match `test/**/*.test.ts`. Its comment names three kinds: pure helpers, the store driven by fake server messages, and components rendered into happy-dom. The real page against a real server is the browser test's job.

Files that need DOMPurify (`markdown.test.ts`, `draft.test.ts`, `transcript.test.ts`) switch to **jsdom** with a `// @vitest-environment jsdom` line: DOMPurify does not work properly under happy-dom (it keeps `javascript:` links).

`web/test/setup.ts` unmounts rendered components after each test (`cleanup()` from `@testing-library/svelte`), so one test's DOM never leaks into the next.

It keeps all user-facing text in one reviewable file.

## Browser test (`test/ui.e2e.mjs`)

The file has 133 `check()` calls; several run only on the fake backend or in branches, so the number of steps in one run is smaller. Not run for this page.

`test/ui.e2e.mjs` drives the built page in headless Chromium (Playwright) against a running test server and saves screenshots. It must run against a test server with its own `XDG_CONFIG_HOME` and `XDG_DATA_HOME`, never the installed app. With `MASTHEAD_E2E_BACKEND=fake` the server uses the fake backend, which answers scripted phrases; checks that need a model's own writing are then skipped. Setup and the settings file are on [Tests](Source-Tests.md#browser-test-testuie2emjs).

What it checks on the page, in order:

- **Sign-in:** no key and a wrong key show the sign-in page; Try again connects once another tab stored the right key; a key in the fragment works and leaves the address; a link with a wrong key, opened fresh or pasted into the open tab, does not sign the browser out.
- **Simple by default:** at most 10 visible controls on first load (the skip link not counted; the plan's target is 7), no jargon in the visible text (tier, Opus, Sonnet, Haiku, effort, sub-agent, lead), no team panel, and an example prompt fills the box without sending.
- **Settings view:** opens from ⚙ with Enter, Escape closes it and gives focus back; "Show helper reports as one line", "Longest a helper may work" and "Show team controls" survive a reload; the Remote access section renders, and on the test server its switch is disabled (the real Tailscale is not used); the team editor refuses an empty name in plain words.
- **Composer:** a message over 400,000 characters is refused and the text comes back.
- **Team:** approval cards appear, name the agent, take focus when nobody is typing and Allow works; the team panel opens by itself in Advanced on a wide window; the per-level stepper; the outline three levels deep, with nothing scrolling sideways at 1440, 900 and 390 px; the guide lines meeting to the pixel (every tick on its parent's line, the line leaving its expander's bottom, the last child's corner taking over where the line ends, at pixel ratios 1 and 1.5); agents named Alpha, Bravo, Charlie, Delta; ← closes a branch and → opens it; the hover preview with real content, Stop from the outline (its word "Stop" shows on a working helper's row; a stopped agent stays, dimmed), "Hide finished", opening a helper and coming back, the message box naming its addressee and Back returning it to the lead; code blocks with a Copy button; reports reaching the lead, folded to one line and opening on click; a table in the final answer; the usage line.
- **Progress without asking** (0.2.1, fake backend only, in a new chat): a helper started in the background makes the chat say "Waiting for 1 helper: <name>"; that button starts closed and Enter opens it; each helper line shows what it is doing and " · under 1 min" or " · N min"; the team row shows the same time; a helper's name opens its chat. Then a question from the main assistant buried under a helper's report brings "Waiting for your answer" by the message box; clicking it highlights the question and moves focus to it (axe-checked), and the marker goes once the person answers.
- **Tidying the team** (fake backend only): `/compact` with automatic tidying on archives without a card and posts a summary; the archived helpers sit under one row and leave the team; an archived chat opens read-only with Restore, and Restore brings the helper back; typing "/" shows `/compact`; with automatic tidying off, `/compact` asks first with the card.
- **Reload:** the chat comes back from disk.
- **Pictures** (fake backend only): a tool image shows as a thumbnail, opens full size, and Escape closes it with focus back on the thumbnail; a PNG attached in an existing chat is uploaded and shown in the sent message; a pasted and a dropped picture are added and uploaded, dragging a picture lights the box up and the light goes after the drop, a picture dropped outside the box does not make the browser open it, and dragged text is left to the browser; the composer is empty after sending; after a reload every sent picture and the tool's picture still load, and a sent picture still opens full size; thumbnails have no blank band under the picture.
- **Phone** (390 × 844, touch, light theme, pixel ratio 2): nothing scrolls sideways, every tap target is at least 44 px, the message box uses 16 px text and is on screen; the chat list starts closed, choosing a chat closes the drawer, the team opens as a drawer and tapping outside closes it; a working helper's Stop square is at least 44 px, fully on screen and shows its word, tapping it stops the helper and the drawer stays open; team rows do not flash the tap colour.
- **Accessibility:** axe-core's WCAG 2 A/AA rules on the first load, the settings view, a chat with the team panel, "Waiting for your answer" (fake only), an archived chat, the tidy card, and the phone's new chat; serious or critical problems fail.
- **Team profiles and Simple/Advanced** (a block appended near the end, marked in the file as pasted in): Simple hides and Advanced shows the thinking-time setting; a new two-level team saves; too many helpers is refused in plain words; editing saves a new level name; an added level saves; then (fake backend) the new-chat screen offers the team chip naming the picked team, a chat on that team shows its messages and runs with 3 levels; declining a removal keeps the team with a plain reason, confirming twice removes a team chats use with no server wording left showing; that chat still shows its own 3 levels and says they can no longer be changed; a new copy is not counted as used by the removed team's chat; a team no chat uses goes after one yes; Simple hides the model line and the team panel's levels and survives a reload.
- **No page errors:** uncaught errors and console errors fail the run, except the refused sockets (403) of the sign-in checks.

## Team screenshots (`team-shots.mjs`)

`web/test/team-shots.mjs` is run by hand: `MASTHEAD_DATA_DIR=<data folder> node web/test/team-shots.mjs http://127.0.0.1:7798 <shots folder>`, against a fresh test server started with `MASTHEAD_BACKEND=fake MASTHEAD_ALLOW_FAKE=1`, whose settings allow 6 Opus, 1 Sonnet and 2 Haiku with `permissionMode` `"default"`. It asks the fake lead to start a three-level branch, a waiting Sonnet, a helper asking to run a command, a failed one, a long-running one (which it stops by hand) and a finished one, then saves `desktop-1440`, `drawer-1000` and `phone-390` in dark and light, and `desktop-1440-dark-hide-finished`. It refuses port 7717.
